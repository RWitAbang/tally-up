Tally Up

The technical blueprint: a plain HTML/CSS/JS web app, a Supabase database with sign-in, and Netlify hosting — so the same tracker opens identically from your phone, laptop, and iPad.

How This Works, In Plain Language

Tally Up is a website, not an installed app — open it in any browser (phone, laptop, iPad) and it's the same app because they're all visiting the same URL.

There's no custom backend server. Your accounts and transactions live in Supabase, a hosted database — think of it as two spreadsheet tabs sitting in the cloud instead of on your laptop: an accounts tab and a transactions tab. Every screen reads or writes rows there directly.

Because this is your personal financial data, you sign in once per device with a single email/password account. Supabase checks every request against that login — without it, the database simply refuses to hand over anything, no matter what URL someone finds.

Netlify hosts the website's files and gives you the one URL that works the same on every device. No framework, no build step — every page is plain HTML, CSS, and JavaScript you can read start to finish.

The Shape of It

What talks to what.

Every device talks to the same Netlify-hosted pages; each page's JavaScript then calls Supabase directly to read or write data. No custom backend server in between.

Data Model

Three tables in Supabase. Every table carries a user_id checked against the signed-in session via Row Level Security — more than one signed-in user strictly needs today, but it means the data is already shaped for more than one person to use this later without a schema change.

Important Failure Modes

No amount entered (or 0) → inline "please enter an amount," submission blocked.
New account, no transactions yet → "no transactions yet" instead of blank space.
Wrong email/password → plain inline error, no lockout logic for a single-user PoC.
Supabase request slow or fails → a loading state while waiting, a plain "couldn't load — try again" on failure.
"Export to Excel" tapped with zero accounts → plain inline message ("add an account first") instead of an empty or broken file.

Decisions Along the Way

🧭 One Genuine Uncertainty

All three new pieces here — the multi-page JS structure, Supabase, and Netlify — are unfamiliar to the learner right now. Rather than discovering a setup problem mid-build, the very first build step is a small, throwaway test: create the Supabase project and its two tables, then build one page that inserts a dummy row and reads it back. That catches key/connection/RLS problems while nothing else depends on them yet.
